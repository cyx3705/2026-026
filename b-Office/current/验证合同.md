## 1.9.0 Release Checks

- `VERIFY-LAYERS`（REQ-UI-049）：`LayerContractTests` 三条——依赖只向下、
  每个源文件都有层、基础层不认识任何组件。
  **写它的时候一条违规都没有**，这是刻意的：它拦的是以后，不是现在。
  两条实现上的判据不能省：**先剥注释**（`AssemblyInfo.cs` 通篇在讲停靠系统，
  一个 `using` 都没有却提了 `HistoryAurora.Shell.Docking` 三次，不剥就是三条假违规，
  而误报的门禁最后一定被删掉），以及**不能只扫 `using`**（`PageDescription` 里的
  `HistoryAurora.Shell.Panels.PanelWidget` 是全限定写的，只扫 using 会被整个绕过）。
  「每个文件都有层」那一条同样不能省——没有它，加一个没人分层的文件夹就等于绕过整套规则。

- `VERIFY-PAGE-SCROLL`（REQ-UI-050）：`PageScrollContractTests` 两条。
  扫描前必须**泵到模板套上为止**并断言至少找到一个 `ScrollViewer`——表格的滚动视图
  来自 `ListView` 模板，不套模板一个都找不到，那时扫出来的「零违规」是假的，
  这条用例会以全绿的形态空转。
  判据是 `TemplatedParent == null` 再排掉自带视口的组件（白名单），
  **不是**「祖先里有没有表格」：第一版按后者判，`TextBox` 的 `PART_ContentHost`
  与下拉框弹出层当场报成违规。

- `VERIFY-PAGE-INSET`（REQ-UI-051，判据加强）：
  `Reload_GivesModulePagesTheSameInsetAsShellPages` 此前只查模块页这一侧，
  名字却写着「与自持页一致」——而 1.8.18 的真实情况是自持页 8、模块页 12，
  用户一眼看出了差别，这条全绿的用例一个字都没说。现在改为**与
  `PageRegistrar.Inset` 的输出逐项对比**（Padding 与 ClipToBounds），
  任一路单独改动立刻红。

- `VERIFY-HOSTED-PAGES`（REQ-UI-052 / 053）：
  `CommandPagesContractTests` 七条 + `ModulesPageContractTests` 三条。
  其中两条是这一版的**核心判据**：
  `EveryHostedPageParsesAndRendersWithoutMissingComponents` ——自持页出现缺件
  说明界面自己的协议表达不了界面自己的页面，1.9.0 的整条论证靠它在缺件出现时立刻变红；
  `EveryHostedActionResolvesToARegisteredCommand` ——断链的形态是「按钮点了没反应」，
  在界面上与「还没选中」完全一样，必须在这里判，不能等人去点。
  取数这一半现在**完全脱离 WPF**，那是把取数从视图挪进指令的附带好处。

- `VERIFY-HOSTED-PAGES` 追加（REQ-UI-055）：
  `TheCommandListFillsUpBeforeAnybodyTypesInTheSearchBox`。
  这条是**先红后绿**写出来的——把命令集改成描述式之后，页面一打开是空的，
  因为搜索框发布的初值是空串而取数把空串当成「还没选」。
  用例必须**真的建窗口并泵到表格填上**：只判「取数命令返回了行」的话，
  取数压根没发出去这件事一个字都测不到，而那正是缺陷所在。

- **真机待验（本轮无法在门禁内覆盖）**：
  1. 四页的实际观感——间隙是否真的与模块页一致、裁切有没有裁掉本该看见的内容；
  2. 命令集删掉两级联动与补全之后，搜索是否够用；
  3. 「热重载」两步指令在真宿主上的成败提示是否仍然可读。
  这三条只能开起来看，门禁给不了结论。

- **本轮记账、未做**：`VERIFY-PAGE-VIEW-OPTIONS` 不存在，因为 `view.filterable` /
  `sortable` / `selection` 至今**没有任何实现**（REQ-UI-054）。这是一张欠条，
  不是一条已完成的要求。

（`%AppData%\HistoryVulcan\Modules\HistoryAurora\`）或经 `vulcan.module.install path=` 安装，

「HistoryAurora 已装载（骨架，尚未接管前端能力）」。
