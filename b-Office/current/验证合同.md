# HistoryAurora 验证合同

## 0.1.0 Release Checks

骨架版本，验收范围限于「仓库形态正确、能构建、能被宿主装载」。

- `VERIFY-BUILD`：`dotnet restore --locked-mode` 与 `dotnet build -c Release` 通过，
  `dotnet format --verify-no-changes` 无差异。
- `VERIFY-MODULE-LOAD`：`ModuleSmoke` 在测试宿主中装载 `HistoryAurora.dll`，
  `AuroraBusinessComposition.Attach` 被调用并取得非空 `IModuleContext`。
- `VERIFY-QUALITY-GATE`：`b-Code-Studio\eng\Test-QualityGate.ps1` 通过，其中必须包含
  「`z-Publish` 未被任何忽略规则覆盖」这一项。
- `VERIFY-HOST-CONTRACT`：`module.manifest.json` 的 `type` 为 `HistoryVulcan.Module`；
  模块工程对宿主运行库的引用为 `Private=false`，`b-Code-Verify` 下三个测试工程为 `Private=true`。
- `VERIFY-VERSION-SINGLE-SOURCE`：全仓 `MinimumHistoryVulcanVersion` 只在
  `AuroraVersion.props` 出现一次，脚本与门禁不得硬编码宿主版本字面量。

**尚未建立**：`VERIFY-COMMAND-PARITY`（迁入首组命令时建立）——用于断言宿主侧退役与本模块
侧接管在同一版本线对齐，`vulcan.command.list` 总数不变、MCP 可见工具数不变。

## 手工冒烟

骨架阶段只需一次：把构建产物放入宿主运行区
（`%AppData%\HistoryVulcan\Modules\HistoryAurora\`）或经 `vulcan.module.install path=` 安装，
确认 `vulcan.module.list` 能列出 HistoryAurora，且宿主日志出现
「HistoryAurora 已装载（骨架，尚未接管前端能力）」。
