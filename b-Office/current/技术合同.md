# HistoryAurora 技术合同

本文件记录现行要求。每项要求有编号、目的、可验证的要求条目和验收方式。

当前源码为 **1.0.0**。消费的宿主版本由 `b-Code-Studio/AuroraVersion.props` 的
`MinimumHistoryVulcanVersion` 单点声明，当前为 **4.0.0**。

## REQ-MOD-001 模块形态与宿主契约（1.0.0）

- 目的：本模块必须是一个可被 HistoryVulcan 装载的标准模块，不得自带第二套基础设施。
- 要求：产出单一程序集 `HistoryAurora.Module.dll`，随 `module.manifest.json`
  （`type = HistoryVulcan.Module`、`ui = true`、`mcpExposure = readonly`）发布。
  实现 `IModuleContextAware`，由宿主在装载时注入 `IModuleContext`；命令一律经上下文注册，
  受 owner 回收。不得自行组装命令总线、日志或设置服务。
- 要求（DEC-007）：程序集内必须有一个公开非抽象的 `BaseVariable.ModuleInfoBase` 子类，
  否则宿主的鸭子类型识别（MD-02）不会把它当模块，只当普通依赖库装载——**编译期无提示，
  运行期表现为「模块管理里没有这一条」**。该类必须显式覆写 `ModuleName` 为 `HistoryAurora`：
  基类默认取程序集名，而程序集名按下一条约束是 `HistoryAurora.Module`，且 ModuleName
  同时就是指令域名，不覆写会让域从 `aurora` 漂走。
- 约束：模块程序集名**不得**与 App 相同（App 也叫 `HistoryAurora`）。同进程内两个同名程序集
  会让 WPF 按短名解析的 pack URI 命中错误的那个；模块无 `.g.resources`，实测导致 AvalonDock
  抛 `IOException 找不到资源 themes/auroratheme.baml`，主界面停靠浮动层失效。
- 要求：引用宿主运行库一律 `Private=false`（部署时由宿主提供）。`b-Code-Verify` 下的测试
  工程是独立宿主进程，必须 `Private=true` 复制私有副本。
- 要求：消费的宿主版本只在 `AuroraVersion.props` 声明一次，发布脚本与门禁从此读取，
  不得各自硬编码字面量。
- 验收：`vulcan.module.list` 与「模块管理」里出现 `HistoryAurora`，与其余四个模块平级；
  `vulcan.command.domains` 的 `aurora` 域不因本模块登记而变化（`MainClassType = null`）；
  `ModuleSmoke` 能在测试宿主中装载本模块并取得上下文；`dotnet build` 与
  `Test-QualityGate.ps1` 通过。
- 关联组件：`b-Code-Studio/Module`（`ModuleInfo.cs`）、`b-Code-Studio/AuroraBusinessComposition.cs`
- 关联验证：`VERIFY-BUILD`、`VERIFY-MODULE-LOAD`

## REQ-UI-001 承接宿主前端能力（1.0.0，已完成）

- 目的：让 HistoryVulcan 只保留指令总线与 MCP，把界面能力移出宿主进程。
- 背景（3.13.0 实测）：`vulcan` 域 81 条命令中 39 条来源为 `frontend:HistoryVulcan.Frontend`
  （ui 21、log 10、app 4、command 4），其 `PolicyVisible` 全为 false，零条投影为 MCP 工具。
- 要求（迁入时逐组细化）：每迁入一组能力，必须在本文件补一条带编号的子要求，写明
  迁入的命令清单、宿主侧对应命令的退役版本，以及两侧不得同时注册或同时缺失的对齐方式。
- 要求（2026-08-19 裁决，改判）：**命令名随实现方改域**，迁入 Aurora 的命令一律从
  `vulcan.*` 改为 `aurora.*`，与 HistoryVulcan DEC-050「指令域跟随实现方，不跟随历史归属」
  一致。本条原先要求「迁入不得改变命令名」，与 DEC-050 直接冲突，已撤销。

  撤销理由不是"服从上游"，而是原要求在实现上站不住：`ModuleDomainNaming.ToDomain`
  会把 owner 强制归一化为域，实测 `vulcan.command.copyexample` 迁入后**名字仍是
  `vulcan.*` 而域已被改写为 `aurora`**——名实不符的中间态既骗不过注册表，也让
  `vulcan.command.domains` 的输出无法解释。要么两边都是 `vulcan`，要么两边都是 `aurora`，
  没有第三种自洽状态；而 Aurora 是独立应用（DEC-004），"两边都是 vulcan"不成立。
- 要求：改名一律走破坏性变更流程——逐条进 Aurora 消费变更摘要，并在宿主侧同步退役。
  与组件键名改名（DEC-005）同批发布，让模块只适配一次。
- 逐条判定结果：见 [前端命令归属判定表V1.0](../history/前端命令归属判定表V1.0.md)。
  39 条中 **37 条归 Aurora 改域**、**2 条归服务侧保留 `vulcan.*`**
  （`command.run` 已搬，`command.help` 待搬——两者都是纯注册表/总线操作，无 UI 依赖）。
  判定依据取源码实测，不按命令名归类。
- 验收：迁入后宿主侧该组命令消失、Aurora 侧以 `aurora.*` 出现；
  `vulcan.command.domains` 中 `vulcan` 域减少的条数等于 `aurora` 域增加的条数；
  MCP 可见工具数不变（这 39 条本就零投影）。
- 状态：**已完成**（随 HistoryVulcan REQ-A7/A8 落地，2026-08-20）。37 条已改域为 `aurora.*`，
  由应用进程注册并上报，来源标记 `frontend:*`；本模块的 `Attach` 仍不注册任何命令
  （DEC-007，`MainClassType = null`——模块只承担注册表身份）。
- 关联验证：`VERIFY-COMMAND-PARITY`（迁入首组时建立）

## REQ-UI-002 组件库承接与家族完整性（规划中）

- 目的：Aurora 承接的不只是「几个页面」，还有一套**已在被三个模块使用**的组件库。
  它决定了模块作者能否长期不碰颜色、不碰模板地做界面。
- 背景（2026-08-19 实测，依据见 `../history/前端组件计划表V1.0.md`）：
  宿主 `Themes/` 现有 2,044 行，其中 `ShellControls.xaml` 1,001 行提供 16 个具名样式，
  `ShellTokens.xaml` 提供 65 个令牌。Janus / Mercury / Minerva 合计引用 30 个不同的
  `Shell.*` 键。Mercury 的两个页面**零自造样式**——现有库足以支撑列表 + 详情类主力页面。
- 要求（键名整体改为 `Aurora.*`，DEC-005）：承接时把 65 个令牌与 16 个具名样式的键
  从 `Shell.*` 改为 `Aurora.*`，家族结构不变（`Aurora.Brush.*`、`Aurora.Button.*`、
  `Aurora.Segment.*` …）。**不得提供 `Shell.*` 别名、不设弃用期、不做双键并存**——
  别名会让每个组件维护两套键、每次演进同步两处，且无法判断模块实际用的是哪一套。
- 要求（资源文件同步改名）：主题文件随键名一起改，不留 `Shell` 字样——
  `ShellTokens.xaml` → `AuroraTokens.xaml`、`ShellTokens.Dark.xaml` → `AuroraTokens.Dark.xaml`、
  `ShellControls.xaml` → `AuroraControls.xaml`、`ShellDocking.xaml` → `AuroraDocking.xaml`、
  `ShellChrome.xaml` → `AuroraChrome.xaml`、`ShellToolTips.xaml` → `AuroraToolTips.xaml`。
  文件名与键名不一致本身就是下一个人要花时间确认的坑。
- 要求（模块不得自建组件，DEC-005）：模块 XAML 中**不得出现 `Style x:Key=` 与
  `<ControlTemplate>`**；颜色、字体、尺寸、控件外观一律取自组件库。该禁令的前提是
  组件库先补齐缺件，见下条。
- 要求（家族完整性，解禁前置）：组件按**家族**维护，不按单点补丁。缺成员时补齐该成员，
  不接受「模块自己造一个」作为长期状态。当前唯一已知缺件：分段家族有
  Bar / Divider / Label / TextBox / ComboBox / Button / CheckBox 七个成员，
  **缺 RadioButton / Toggle**，Janus 因此自造 40 行 `OperationSegment`。
  **`Aurora.Segment.Toggle` 未落地前不得对模块执行自建禁令**——先断人后路再补路，
  只会逼出更难发现的绕行写法。
- 要求（静默退化必须可查，DEC-005 的代价对冲）：`DynamicResource` 找不到键时 WPF
  **不抛异常**，只是不套用该值。模块在适配前不会崩，而是静默退化成 WPF 默认外观。
  因此必须提供一个可执行检查器，扫描给定路径下的 XAML 并报告：
  ① 残留的 `Shell.*` 引用；② 自建的 `Style x:Key=` / `<ControlTemplate>`；
  ③ 字面颜色（`#RRGGBB`、`Colors.*`）。检查器要能对**模块仓**运行，使「哪些模块尚未适配」
  成为可查询事实，而不是靠肉眼发现哪一页变丑。
- 要求（表格技术选型）：表格能力围绕 `ListView` + `GridView` 建设。实测 12 个页面里
  ListView 用 21 次、GridViewColumn 46 次，`DataGrid` 仅 2 次——`DataGrid` 不纳入主题化范围，
  避免维护两套表格外观。
- 要求（资源引用方式）：一律 `DynamicResource`。`StaticResource` 在主题切换后不更新，
  且键名重构期间它会在**编译期**就失败——两种失败模式混在一起会让排查更难。
- 验收：承接后 `Themes/` 内不存在任何 `Shell.` 前缀的键（含注释外的字符串）；
  检查器对三个模块仓运行，输出的待适配清单与实际情况一致；
  `Aurora.Segment.Toggle` 落地后 Janus 可删除自造模板且外观不变（浅色与深色各一次目视核对）。
- 关联组件：`Themes/`（承接自宿主 `ShellTokens.xaml` / `ShellControls.xaml` / `ShellDocking.xaml`）
- 关联验证：`VERIFY-UI-TOKENS`（承接时建立）

## 已裁决：命令随实现方改域（2026-08-19）

**裁决结果：依 HistoryVulcan DEC-050，撤销 REQ-UI-001 中「迁入不得改变命令名」一条。**

迁入 Aurora 的命令一律 `vulcan.*` → `aurora.*`。

裁决依据是实测事实而非孰先孰后：该命令的域**已经**被宿主按 REQ-CMD-011 强制改写为
`aurora`，而名字仍是 `vulcan.command.copyexample`——当前正处于「域是 aurora、名是 vulcan」
的名实不符状态。这说明 REQ-UI-001 的「只变注册方、其余不变」本就不成立，它描述的是一个
运行时不存在的状态。

被否决的另一条路（保名）代价更大：需要宿主放弃对模块命令域的强制改写，
而那条改写是 REQ-CMD-011 的全局一致性基础，为一个应用破例会让「模块域由 owner 强制」
这条规则失去意义。

**施工约束**：39 条前端命令逐条判定，不一刀切——判定标准见 DEC-050
（真实依赖 UI 的随 Aurora 改域；只依赖总线的归服务侧保留 `vulcan.*`）。
改名与组件键名改名（DEC-005）**同批发布**，让模块只适配一次。

## REQ-UI-003 页面注册走指令总线（1.0.0，协议 V1 已实施）

- 目的：让模块不再经宿主声明的接口注册界面，也不再构造任何 WPF 对象。
  详见 [页面注册协议方案](页面注册协议方案.md)。
- 要求：模块以 `<域>.ui.describe` 返回页面描述 JSON；Aurora **主动拉取**，
  宿主不持有描述。拉取而非缓存是刻意的——宿主侧 `web.frontendcatalog` 采用
  「缓存 + 连上时重放」，按客户端名做键且不回收，前端改名一次即留下永久幽灵条目。
- 要求：模块只连宿主总线，**不引用 Aurora 任何程序集**；命令归 `aurora` 域，
  宿主只路由不解释载荷。
- 要求：描述中**不得出现样式键或颜色**，只能选语义档位（accent / ghost / danger /
  caption / secondary），映射写死在 `PageRenderer` 内（DEC-005）。
- 要求：未知组件渲染为**显式占位**并计入缺件清单，`aurora.ui.missing` 可查。
  **不得静默省略**——静默失败正是本协议要消灭的形态。
- 要求：单个模块的描述损坏、渲染失败或声称他人 owner 时，**只跳过该模块**，
  其余模块照常建页。
- 要求：重拉必须先撤后建，注册是派生状态，不得累积。
- 验收：`PageProtocolContractTests`（11 条）+ `ModulePageLoaderContractTests`（6 条）全绿；
  `aurora.ui.reloadpages` / `aurora.ui.invalidate` / `aurora.ui.missing` 三条命令注册成功；
  `vulcan.command.list mcp=visible domain=aurora` 返回 0 条（实测 2026-08-20）。
- 状态：**Aurora 侧已实施**；尚无模块提供 `ui.describe`，因此实测拉取为
  「问了 0 个模块，建了 0 页」。模块适配属于下一轮。
- 要求：拉取必须**合并重入请求**。冷启动实测连触发三遍（ModuleHost 初次装载一次，
  宿主 moduleRevision 通知引发的 `ReloadConfirmedSources` 再两次），不合并即三倍
  describe 调用与三轮建撤抖动。
- 未尽项（原列三条，前两条已完成）：
  1. ~~下行通知~~ **已完成**——机制本就存在（`moduleRevision` 广播），
     Aurora 侧订阅链路已连通，另加重入合并；
  2. ~~MCP 硬排除~~ **已完成**——宿主 `McpExposurePolicy` 按后缀排除
     `<域>.ui.describe` / `<域>.ui.data`，按名排除三条 `aurora.ui.*`；
  3. 组件申请通道未定，`Aurora.Segment.Toggle` 仍缺（占位已生效）。
- 关联组件：`b-Code-Studio/Shell/Pages`、`b-Code-Studio/Shell/BuiltinCommands.Pages.cs`
- 关联验证：`VERIFY-BUILD`

## REQ-REL-001 发布真值与不可变性（0.1.0）

- 目的：区分可编辑源、当前候选与历史归档。
- 要求：`z-Publish/` 根部保存当前候选，`z-Publish/history/<发布标识>/` 保存不可变归档。
  两者都纳入 git，任何忽略或排除规则不得触碰 `z-*`。
- 要求：不直接编辑 `z-Publish/` 内容；修改权威源后经 `Build-HistoryAuroraPackage.ps1` 生成。
- 验收：`Test-QualityGate.ps1` 检查 `z-Publish` 未被忽略规则覆盖。
- 关联验证：`VERIFY-QUALITY-GATE`
