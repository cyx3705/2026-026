## 为什么要换

### 顶栏一行做了三件事

主窗口今天没有独立标题栏：页签行同时是

| 职责 | 现在的实现 |
|---|---|
| 窗口外框（拖动、双击最大化、最小化/关闭） | `ShellWindow.Chrome.cs` 的 `AttachChromeBarToMainDocumentPane` / `ReserveSpaceForChromeBar`；`ShellTopBarCoordinator` 的 `HandleMain*` / `BeginHostWindowGesture` / `RestoreHostWindowUnderPointer` |
| 全局导航（所有模块的页面排成一排） | 页签条本身 |
| 场景内的页面切换（停靠、标签组、浮出） | 页签拖拽与浮动逻辑 |

`ShellTopBarCoordinator` 两个文件约 1250 行、`ShellWindow.Chrome*.cs` 约 650 行，其中相当一部分
是在让「页签兼标题栏」这件事成立。模块越多，这一行越长；而每个模块要的控制面板组合不同，
顶栏状态就不断被改来适配。

### 主页面的组织单位从来没定过

同体量的两个模块走到了两个极端：

- **Janus**：三页协同——`overview`（中央，标题 Janus）、`projops`（左侧 0.38）、
  `graph`（并入 `console` 的标签组），由跨页通道 `janus.project` 串起来。
- **Minerva**：只有 `mapping` 一页，五种转换内容收在一个由 `minerva.content` 驱动的 `switch` 里。

两边各自都对：Janus 围绕一个要被多个视图**同时**看的对象（项目），Minerva 是一次一个任务的流程。
错在没有规则——而在全局页签条下，用 Minerva 时 Janus 的三页和其它模块的页全都挂在眼前，
它们对当前任务是多余的。

### 结论

**主页面的组织单位是场景。** 切场景就是换掉整个停靠布局；不在当前场景里的页面不出现。
全局页签条退役，由外围导航器承担「去哪」；页签只在场景内部负责停靠与切换。

## 一、模型

```
场景 = 页面集合 + 停靠布局（含浮动窗口） + 通道初值
```

### 1.1 三种来源，一本账

| 来源 | 怎么来 | 可删 |
|---|---|---|
| **派生**（`derived`） | 每个声明了页面的模块自动得到一个场景，含该 owner 的全部页面 | 否，随模块装卸而生灭 |
| **用户**（`user`） | `aurora.scene.save` 另存当前场景 | 是 |
| **模块声明**（`module`） | `<域>.ui.describe` 的可选 `scenes` 段（阶段四） | 否，随模块 |

派生规则已经覆盖今天的两个极端，**不需要任何模块改代码**：
Janus 三页 owner 都是 `HistoryJanus`，派生结果正是那个三页场景；Minerva 派生结果只有 `mapping`。
模块声明留到最后，等真实使用验证过 schema 之后再开（理由同 REQ-UI-054 的教训：不写没实现的字段）。

派生场景与模块场景的**布局改动照样保存**，只是存为该场景的用户覆盖层；`aurora.scene.reset` 丢弃覆盖层。

### 1.2 常驻页

控制台这类跨场景页面标记为常驻：每个场景自动带上，不必在每个场景里各存一份。
v1 常驻集只有 `console`，写在 Aurora 自己的配置里，不开放给模块声明。

`graph` 的 `tabTarget = "console"` 因此在任何含 `graph` 的场景里都成立。

### 1.3 页面实例跨场景复用

`DockingHost.GetOrCreateContent` 已按页面 id 缓存内容对象（`_contents`），
`ApplyLayoutSnapshot` 重建的是停靠模型，**不是页面视图**。所以切场景不会丢页面状态
（Minerva 选好的来源、Janus 选中的项目），通道值也仍在 `SelectionChannels` 里。
本方案依赖这条现成行为，并为它加一条契约测试（REQ-UI-086），防止将来有人把缓存改掉。

### 1.4 关闭页签的语义

场景内关闭页签 = **从当前场景移除这一页**，不是全局隐藏。别的场景不受影响。

## 二、存储

沿用布局目录与 `FileLayoutStore` 的原子写法，新增一种文件：

```
layout/scenes/<场景 id>.scene.v1.json
```

```json
{
  "schemaVersion": 1,
  "id": "janus",
  "title": "Janus",
  "source": "derived",
  "owner": "HistoryJanus",
  "pages": ["HistoryJanus/overview", "HistoryJanus/projops", "HistoryJanus/graph"],
  "channels": { "janus.section": "Git 文件规则" },
  "layout": { "…": "DockLayoutSnapshot，原样内嵌" }
}
```

- 页面引用写 `owner/id`。页面 id 目前只是「进程内唯一」的约定，跨模块重名会在场景引用里变成静默错配。
- 派生场景只落盘用户覆盖层（`layout` 与 `channels`）；`pages` 每次从注册表重新派生，不缓存——
  与页面注册协议 §1.2「宿主不缓存」同一条理由。
- 另有 `layout/scenes/active` 记当前场景 id，重启恢复。

### 迁移

首次启动时，现有 `layout.v1.json` 转成一个用户场景「默认」，包含它里面的全部页面，
并设为当前场景——**升级后第一眼看到的界面与升级前一致**。
命名布局（`aurora.ui.layoutsave`）原样保留、照常可用，是否并入场景留作未决问题。

## 三、切换算法

```
aurora.scene.go id=<场景>
  1. 把当前布局写回当前场景（覆盖层）
  2. 目标页面集 = 场景.pages ∪ 常驻集，逐个对照注册表
       缺失的页面：记 Warn，并计入该场景的断链清单（scene.list 可见）——不静默跳过
  3. 有布局快照 → ApplyLayoutSnapshot（只含目标页面集）
     无快照     → 按各页 placement 生成，等价于只对目标页面集做 ResetLayout
  4. 写入通道初值
  5. 激活快照里的 ActiveContentId；记 active
```

第 3 步里注册了但不在目标集的页面不进停靠树，其位置记忆仍留在 `_orphanPlacements`，
视图仍在 `_contents`。

## 四、命令（v1）

| 命令 | 性质 | 说明 |
|---|---|---|
| `aurora.scene.list` | readonly | 列出全部场景：id、标题、来源、页面数、断链数、是否当前 |
| `aurora.scene.go id=` | standard | 切到场景 |
| `aurora.scene.save id= title=` | standard | 当前页面集 + 布局 + 通道另存为用户场景 |
| `aurora.scene.add page=` | standard | 把一页加入当前场景（Minerva 与别的页混用就走这条） |
| `aurora.scene.remove page=` | standard | 从当前场景移除一页 |
| `aurora.scene.reset` | standard | 丢弃当前场景的覆盖层，回到派生/声明形态 |
| `aurora.scene.delete id=` | standard | 删除用户场景；派生与模块场景拒绝 |

全部 `RequiresUiThread = true`，前端注册（`FrontendCommandCatalog.Source`）。
Aurora 的 `mcpExposure` 是 `readonly`，因此默认只有 `scene.list` 对模型可见；
`scene.go` 要不要对模型开放，单独判（见未决问题）。

## 五、导航器

**不做成停靠页面**——那样它自己要占位置，还会卷进每个场景的布局。形态：

- **左侧窄栏**：置顶与最近使用的场景，替代今天的全局页签条；
- **搜索浮层**：快捷键呼出（暂定 `Ctrl+K`，施工时核对控制台输入框的键位冲突），

  > **1.20.3 作废（DEC-035，REQ-UI-106）**：浮层删除，搜索改为右栏第二行的一个输入框，
  > 随输入筛下面的场景与常用页面两段；动作不再进索引。快捷键与 `aurora.nav.open` 保留，
  > 落点改成「聚焦这个搜索框」。以下关于浮层的描述只作历史。

  索引覆盖场景、页面、动作；页面条目提供「单独打开」与「加入当前场景」两个动作。

索引一律**派生**：行来自场景清单、页面注册表、动作注册表，不落盘；检索文本只用已声明的字段
（标题、owner、动作 summary），不新增要人工维护的关键词。输入框复用 `AuroraSuggestBox`，不另造控件。

`switch` 分支（Minerva 的五种转换内容）作为「页面 + 通道值」进索引，放在阶段二的第二步。

## 八、未决问题

1. **命名布局去留**：`aurora.ui.layout*` 与用户场景功能重叠。并入（布局方案 = 无页面集约束的场景），
   还是保留为「当前场景内的布局变体」？
2. **`scene.go` 是否对模型开放**：开放后「切到 Minerva」是一次 MCP 调用，但它改的是用户眼前的界面。
3. **常驻集是否开放配置**：v1 只有 `console`；Aurora 自持页（命令集、模块管理、指令详情）目前归入
   派生场景「Aurora」，是否有页面也该常驻，用一段时间再定。
4. **快捷键**：`Ctrl+K` 与控制台输入框、Mercury 全局热键的冲突待核。
5. **场景膨胀**：场景多了会重演今天的问题。对策是只靠同一个搜索入口 + 使用频次排序，
   **不给场景做专门的管理页**；若仍不够再议。

### 与草案不同的地方

- **存储（§二）**：没有新开 `layout/scenes/*.scene.v1.json`。布局按拍板存命名布局
  （`<场景 id>.layout.v1.json`），用户改动与当前场景存设置键 `aurora.scenes`，频次存 `aurora.nav.usage`。
  少一种文件，也少一处与命名布局各说各话的可能。
- **迁移（§二）**：没有生成「默认」用户场景，改为内置场景「全部」（id `all`，含每一页）作为升级后的默认。
  效果相同——升级后第一眼与升级前一致——但它不会随用户改动变形，任何时候都能回到「全都在」。
- **常驻集（§1.2）**：草案只写了 `console`。实施发现命令集是主文档区的锚点
  （`NeedsCentralWorkspaceRepair` 在它不在文档区时判需修复，窗口按钮栏也挂在那个窗格的页签行上），
  藏不掉，因此一并常驻。解开它属于拆顶栏（REQ-UI-091）。
- **关闭页签（§1.4）**：未实现「关闭页签 = 移出场景」。关闭仍是隐藏，但隐藏状态记在**这个场景**的布局里，
  别的场景不受影响，体验上等价；要显式移出走 `aurora.scene.remove`。
- **通道初值（§一）**：未实现。页面实例跨场景复用、通道值在内存里一直在，切场景本来就不丢；
  只有跨重启才用得上，而往别的控件拥有的通道里写值会与控件显示失配（同 REQ-UI-090 的理由）。
  按「不写没实现的字段」的规矩，场景设置里没有 `channels` 这一项。
- **指令（§四）**：多一条 `aurora.scene.open page=`——导航器里「打开一页」需要一个落点，
  它对模型同样有用。
- **导航器（§五）**：左栏宽 128，列「全部」+ 常用前 12 + 当前场景，按标题排。动作条目只定位不执行。
- **阶段三、四**：未启动。

## 十、1.20.0 调整（DEC-032，REQ-UI-094 ～ 099）

用户在「顶栏退役」这一轮拍板的几条，把上面的模型与第六、七节的施工顺序一起改了：

| 原方案 | 1.20.0 |
|---|---|
| §一 场景 = 页面集合 + 停靠布局 + 通道初值 | **场景 = 一份命名布局**。场景不拥有页面，区别只是显隐；`scene.add / remove` 删除 |
| §1.1 派生场景「含该 owner 的全部页面」 | 那只是**初值**：第一次进入（或重置）时露出该模块的页与常驻页，之后按离开时的样子 |
| §1.2 常驻集 `console` + `mcp`（mcp 是被迫的） | 仍常驻，但命令集**解除锚点**：可以被顶掉、藏掉、浮出 |
| §五 导航器左栏 | 搬到**右栏**，顶部接下窗口控制组，下半是常用页面胶囊 |
| §六 窗口外框迁到固定细标题栏 | 改为迁进右栏顶部；顶栏（主文档区页签行）本版**只剩一页**，本身还在 |
| — | 页面拖动改为 Ctrl 标签态；拖出落空即隐藏；工具页 ▼ ✕ 删除 |

REQ-UI-087（断链）随页面集合一起作废。顶栏本身的删除仍是 REQ-UI-091 的剩余部分。
