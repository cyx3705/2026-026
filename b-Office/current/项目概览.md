# HistoryAurora 项目概览

## 定位

OneHistory 体系的**前端应用**，编号 2026-026。名字取自罗马黎明女神 Aurora——本项目是
整个体系对用户可见的那一面：窗口、布局、控制台与主题。

**它是宿主装载的界面模块**（DEC-008 推翻了 DEC-004 的独立 exe 两条）。
启动与显隐走注册指令，发布只有模块包。DEC-004 仍有效的是自持命令注册表与 Core 解冻。

宿主指令与公开 API 以 `../2026-023-HistoryVulcan/b-Office/package/` 为准，本仓不复述。
界面视觉与嵌入页结构见 [HistoryAurora_UI风格与嵌入页面规范.md](HistoryAurora_UI风格与嵌入页面规范.md)。

## 体系位置

OneHistory 体系此前含 5 个项目（Diana 019、Janus 020、Mercury 021、Vulcan 023、Minerva 024）。
HistoryAurora 是第 6 个，也是唯一专职承载界面的项目——它是应用，不是模块形态的界面库。

**1.9.2。** 六条要求，可以归成三件事：**一根漏接的线、一块重做的版面、

一、**命令集空了两版**（REQ-UI-057）。页面表头齐全、控制面板在、一行数据都没有，
日志里一个字也没有。查下来是装配根漏了 `Catalog = _catalog` 这一行——1.9.0 把命令集
与指令详情改成描述式时，取数从视图里的私有状态换成了 `aurora.ui.data`，
而目录会话从来没接上来。它两版没被发现，是因为当时那一路「拿不到会话就返回空表」：
**「没接线」与「真的一条指令都没有」从此在界面上、在日志里完全一样**。
现在改判失败，并且门禁同时守两侧——一条验「没接线会报错」，
一条验「这台机器接上了」，只有前者的话装配根再漏一次仍然全绿。

顺带把这一页重排了（REQ-UI-058）：列改成【域 / 类 / 方法 / 只读 / 说明】——
旧版第一列的完整指令名重复了紧随其后两列的全部内容，而真正有区别的方法名
被挤在最左边一列的末尾。行内按钮那一列删掉，四条动作只进右键菜单，
另外在指令详情页顶上补了一个控制面板放同样三件事。
`name` 这个键**留在行数据里**：去掉一列是版面决定，去掉一个键是断链。

二、**控制面板的行成了一等结构**（REQ-UI-060，破坏性）。此前面板有两套互不相干的排版，
由 `orientation` 二选一，而两套都表达不了「这三个是一行、那一个自己一行」——
竖排里行是 `inline` 的副产品，横排里行是宽度算出来的结果。
现在 `widgets` 换成 `rows`，每行自己说是均布（余量等比放大）还是可变宽度
（余量全给一个）；元素按最窄宽度排，**放得下就不换行，放不下才折**，
而折出来的仍然是同一个声明行——折行是宽度不够时的应对，不是版面结构的变化。
`orientation`、`inline`、`required` 三个字段一并退役（DEC-020），
Janus 与 Mercury 的声明同步改写。

同一版把面板上下那圈「厚边框」收掉（REQ-UI-061）：它不是边框，是底板 Padding 2、
面板内缩 4、控件自带 Margin 3～6 三层叠加。控制台顶栏用的是**同一份底板样式**却只有 2，
于是同一个 `Aurora.Panel.Surface` 在两处看上去完全不是一个东西。

三、**还上 1.8.18 记的那笔能力欠账**（REQ-UI-059，DEC-019）。选择框新增
`optionsSource`：候选来自一条只读指令，参数里可以引用选择通道，通道一变就重取。
命令集的域/类两级联动下拉据此恢复。DEC-018 定的「组件保持克制」不是「永远不加」——
它真正的价值是「界面自己先撞上缺件」，而撞上之后正确的兑现方式是补组件，
不是给某一页开后门。

另外补回一个很早以前有过的能力：**表格列可以拖着换顺序，并且记得住**
（REQ-UI-062）。一律可拖、不加声明；占满剩余宽度的那一列钉在最右——
它不在最后就没有「剩余」可占。

### 1.9.1

一件事：**弹出层多了一条打开它的路——右键**（REQ-UI-056）。

来源是 Mercury 的扩展坞管理页：顶上常驻着「加入扩展坞」面板（一个输入框加四个按钮），
一周用不到一次，而这一页真正要看的是下面那张条目表。1.9.0 之后页面不滚，
**被它挤掉的高度就是看不见的行**——版面从审美问题变成了功能问题。

弹出层（1.7.0）本来就是为这个造的，但它自带一个按钮，仍然占一行。所以这一版
**不新建组件**：先查了仓里已有的三处右键实现（表格行操作菜单、轮换选项框候选菜单、
控制台复制菜单），三处都是动作菜单、放不进输入框；能复用的是浮层本体，
它缺的只是一个触发方式。于是给 `popup` 加一个 `trigger`，浮层本体一行不动。

施工中撞出的一条实测教训记在 REQ-UI-056：WPF 的 `Popup` 在 `Collapsed` 的父级下
**开不出来，且不抛异常也不触发 `Closed`**——第一稿正是这么写的，表现为"右键完全没反应"，
而除了真的去开一次，没有任何地方会说出这件事。门禁因此必须建窗口并真的打开一次。

### 1.9.0

三件事，其实是同一件：**让界面自己活在自己的规矩里**。

一、界面分三层写进合同并加了门禁（基础层 = 页面外壳，组件层 = 演进层，
页面层 = 自持的那几页）。逐目录比对下来依赖方向**本来就是干净的单向**，
所以这条不是重构，是把既成事实变成约束——没有门禁的分层会在第一次「就这一次」里破掉。

二、工具页不再有页面级滚动，装不下就裁掉，滚动只发生在表格、泳道这类自带视口的组件里。
此前「鼠标停在控制面板上滚不动、挪开又能滚」是两套滚动语义打架，退场的该是外面那层。

三、Aurora 自持的四页全部改成页面描述，与模块页共用同一个渲染器与包边。
用户发现的「Aurora 的页和别的模块间隙不一样」查实是两条通道：自持页写 8、模块页写 12，
而代码里没有任何一处「说了算」的地方可以改它，因为根本不存在那样一处。

第三件的真正意义不在那 4px。此前只有组件测试页是描述式的，另外三页是手搓 WPF，
于是「模块不得自建组件」这条禁令，界面自己是全仓最大的违反者；组件层缺什么，
只有模块作者撞得到、又补不了。逼界面自用之后，**缺件由界面自己先撞上**。

本轮定的原则是「页面适配组件、组件保持克制」，因此净新增组件能力为 **0**：
凡是现有组件表达不了的一律削页面——删掉了域/类两级联动下拉、命令集搜索框的补全、
三页的状态行。逐条记在 REQ-UI-052，不假装没发生。

顺带撞出一条旧缺陷：`view.filterable` / `sortable` / `selection` 在 schema 里声明、
解析器里解析，**全仓没有一处读它**。这正是这套协议要消灭的失败形态，
只不过这次是协议自己犯的。记在 REQ-UI-054，本版不实现也不删。

**1.8.17。** 通道从「表格单向发布」变成**双向的接线柱**：控制面板的文本框与轮换选项框
可以声明 `channel`，把自己的当前值发上通道（REQ-UI-045）；页面这一层新增 `switch`
容器，按通道值决定显示哪一支（REQ-UI-046）。两件合起来才是「三个页签收进一页」——
Janus 5.4.6 把 Git 文件规则 / 分支历史 / GitHub 三页收进「项目操作」页，用的就是这条。

**它换的是组件，不是页面。** 三支各自还是普通的 `stack` / `table` / `panel`，
只是同一时刻只有一支挂在可视树上。挂树而不是显隐是拿代价换来的：折叠元素照样收
`Loaded`，写成显隐的话三支的取数会在开页那一刻一起打出去，而 Janus 的规则落地状态
那一支每次跑两条 `git ls-files`。

同轮补掉一处**模块无法自救的差异**：走描述协议的模块页此前被直接挂进窗格，
第一个控件贴着窗格边框画，而界面自持的 XAML 页按规范自己写了 `Aurora.Space.Pad`。
描述里没有任何字段能表达内边距——看得见、改不动。现在由装载器统一补上（REQ-UI-047）。

**1.8.16。** 把 1.8.14 弄丢的「表格选中行 → 按钮变可用」接回来，并且**跨页面**可用：

**1.7.4。** 浮窗叠不回去的第三轮，前两轮的判断已作废。反编译确认 AvalonDock 的
`FilterMessage` 只看 WM_SYSCOMMAND(仅最大化/还原)/WM_LBUTTONUP/**WM_MOVING**/WM_EXITSIZEMOVE，
不看非客户区消息；建 DragService（那组蓝色指示）的是 `WM_MOVING → UpdateDragPosition`，
而且反射直调验证过它能建起来——**停靠机制本身是好的**。
真正的缺口是 `DragMove()` 之前没放掉 Win32 鼠标捕获：捕获还在，系统的移动循环就不启动，
`DragMove()` 静默地什么都不做，一条 WM_MOVING 都不发。
`CaptionHeight` 回到 0，`WM_NCLBUTTONDOWN` 的做法撤销。

**1.7.3。** 双击标题聚焦的 `NotSupportedException` 找到根因并修掉：
`XmlLayoutSerializer` 走 `XmlSerializer`，而 AvalonDock 随模块包装进宿主的
**可回收 AssemblyLoadContext**（Aurora 是 `pinned:false`），对其中的类型做 XML 序列化
直接报「非可回收程序集不能引用可回收程序集」。门禁里复现不出来——测试进程把 AvalonDock
装在默认上下文里。聚焦与还原改为留住那棵 `LayoutRoot` 的引用，不再经 XML。
**同一根因还解释了另一件事：布局持久化一直是坏的**（`layout` 目录始终是空的），
那一条本轮未修。

AvalonDock 要的 `WM_NCLBUTTONDOWN`/`HTCAPTION` 始终没发出去，所以装上去仍然叠不回去。

## 要解决的问题

HistoryVulcan 3.13.0 实测：`vulcan` 域 81 条命令中 39 条由前端进程注册
（`frontend:HistoryVulcan.Frontend`），构成为 ui 21、log 10、app 4、command 4。
这 39 条的 `PolicyVisible` 全为 false——**零条投影为 MCP 工具**，却占着服务进程注册表
近一半条目，并参与每次 schema 导出与目录快照。

把它们迁到本模块后，宿主可以只保留指令总线与 MCP，而 MCP 工具面一个不少。

## 迁移策略

**不再按命令分组零敲碎打**，改为整体切出——`HistoryVulcan.Shell` 12,712 行连同 `App` 的
前端半边一次迁入，产出 `HistoryAurora.exe`。详见
[前端切出迁移方案.md](前端切出迁移方案.md)（REQ-A1..A4 / B1..B2 / C 阶段）。

按命令分组迁移的方案（曾计划 `log.*` 先行）已被实测否决：前端命令依赖 `ShellWindow`、
`ConsoleView`（21 处引用）、UI 线程，而模块命令只落服务进程，路径根本不通。
且 `log.*` 并非"耦合最浅"——它是全组里最深的。
