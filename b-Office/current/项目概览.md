# HistoryAurora 项目概览

## 定位

OneHistory 体系的**前端应用**，编号 2026-026。名字取自罗马黎明女神 Aurora——本项目是
整个体系对用户可见的那一面：窗口、布局、控制台与主题。

**它是宿主装载的界面模块**（DEC-008 推翻了 DEC-004 的独立 exe 两条）。
启动与显隐走注册指令，发布只有模块包。DEC-004 仍有效的是自持命令注册表与 Core 解冻。

宿主指令与公开 API 以 `../2026-023-HistoryVulcan/b-Office/package/` 为准，本仓不复述。
界面视觉与嵌入页结构见 [HistoryAurora_UI风格与嵌入页面规范.md](HistoryAurora_UI风格与嵌入页面规范.md)。

## 体系位置

OneHistory 体系此前含 5 个项目（Diana 019、Janus 020、Mercury 021、Vulcan 023、Minerva 024）。
HistoryAurora 是第 6 个，也是唯一专职承载界面的项目——它是应用，不是模块形态的界面库。

## 当前状态

**1.8.17。** 通道从「表格单向发布」变成**双向的接线柱**：控制面板的文本框与轮换选项框
可以声明 `channel`，把自己的当前值发上通道（REQ-UI-045）；页面这一层新增 `switch`
容器，按通道值决定显示哪一支（REQ-UI-046）。两件合起来才是「三个页签收进一页」——
Janus 5.4.6 把 Git 文件规则 / 分支历史 / GitHub 三页收进「项目操作」页，用的就是这条。

**它换的是组件，不是页面。** 三支各自还是普通的 `stack` / `table` / `panel`，
只是同一时刻只有一支挂在可视树上。挂树而不是显隐是拿代价换来的：折叠元素照样收
`Loaded`，写成显隐的话三支的取数会在开页那一刻一起打出去，而 Janus 的规则落地状态
那一支每次跑两条 `git ls-files`。

同轮补掉一处**模块无法自救的差异**：走描述协议的模块页此前被直接挂进窗格，
第一个控件贴着窗格边框画，而界面自持的 XAML 页按规范自己写了 `Aurora.Space.Pad`。
描述里没有任何字段能表达内边距——看得见、改不动。现在由装载器统一补上（REQ-UI-047）。

**1.8.16。** 把 1.8.14 弄丢的「表格选中行 → 按钮变可用」接回来，并且**跨页面**可用：
表格用 `channel` 声明把选中行发上一条界面级通道，控制面板用 `follows` 跟随取值、
用 `enabledWhen` 按有无选中启停，动作参数用 `{selection.<通道>.<列>}` 取选中行
（REQ-UI-041）。落点从页内节点 id 换成界面级通道，是"能跨页"的全部原因——
Janus 的项目表在中央页、操作面板在左侧页，页内 id 到不了对面。

同轮还有一件：取数不再只在建页时跑一次——参数可以引用选中行，通道一变自动重取，
也能被 `aurora.ui.refreshdata` 显式刷新（REQ-UI-044）。没有它，「刷新」按钮只能把
指令打到控制台，而依赖选中的表换一次选中就成了过期数据。

同轮两件：`stack` 改成按行分档的 Grid，表格与泳道图拿剩余尺寸，
修掉「表格撑满整页且滚不动」（REQ-UI-042）；面板按钮可声明 `inline` 与前一个控件同行，
一行因此是「左标签 / 中控件 / 右按钮」（REQ-UI-043）。

**外加一处既有缺陷**：动作占位符正则是 `\w+`，不含连字符，
`{project-name}` 这类控件 id 从来没被识别为占位符，原样上了总线。写用例时才撞出来。

**1.7.5。** 加了一套**真实鼠标**冒烟（`FloatingDockMouseSmoke`，默认不跑，
`AURORA_MOUSE_SMOKE=1` 开启），专门覆盖"浮窗拖回来合并成页签组"这条链路——
它此前在门禁里驱动不了，改了三轮全靠推理，推错过两次。
**实测全绿、连跑两次稳定**：1.7.4 那个修法（拖动前放掉 Win32 鼠标捕获）成立。
同时给 `TryDragWindow` 加了进出日志，真机上拖不动时先看这两条在不在。

**1.7.4。** 浮窗叠不回去的第三轮，前两轮的判断已作废。反编译确认 AvalonDock 的
`FilterMessage` 只看 WM_SYSCOMMAND(仅最大化/还原)/WM_LBUTTONUP/**WM_MOVING**/WM_EXITSIZEMOVE，
不看非客户区消息；建 DragService（那组蓝色指示）的是 `WM_MOVING → UpdateDragPosition`，
而且反射直调验证过它能建起来——**停靠机制本身是好的**。
真正的缺口是 `DragMove()` 之前没放掉 Win32 鼠标捕获：捕获还在，系统的移动循环就不启动，
`DragMove()` 静默地什么都不做，一条 WM_MOVING 都不发。
`CaptionHeight` 回到 0，`WM_NCLBUTTONDOWN` 的做法撤销。

**1.7.3。** 双击标题聚焦的 `NotSupportedException` 找到根因并修掉：
`XmlLayoutSerializer` 走 `XmlSerializer`，而 AvalonDock 随模块包装进宿主的
**可回收 AssemblyLoadContext**（Aurora 是 `pinned:false`），对其中的类型做 XML 序列化
直接报「非可回收程序集不能引用可回收程序集」。门禁里复现不出来——测试进程把 AvalonDock
装在默认上下文里。聚焦与还原改为留住那棵 `LayoutRoot` 的引用，不再经 XML。
**同一根因还解释了另一件事：布局持久化一直是坏的**（`layout` 目录始终是空的），
那一条本轮未修。

**1.7.2。** 浮窗拖动交回标题栏拖动——1.7.1 只抬起了 `CaptionHeight`（前提条件），
而 Aurora 自己接管了浮窗页头的拖动、仍走 `Window.DragMove()`，
AvalonDock 要的 `WM_NCLBUTTONDOWN`/`HTCAPTION` 始终没发出去，所以装上去仍然叠不回去。
现在按 AvalonDock 自己 `AttachDrag` 的那一招把消息发出去。**只能真机确认手感。**
同轮修掉命令集那条横向滚动条（星号列改以滚动视口为准）与模块管理被挤没的描述列
（定宽列各收一档 + 截断的字可悬停看全）。

## 要解决的问题

HistoryVulcan 3.13.0 实测：`vulcan` 域 81 条命令中 39 条由前端进程注册
（`frontend:HistoryVulcan.Frontend`），构成为 ui 21、log 10、app 4、command 4。
这 39 条的 `PolicyVisible` 全为 false——**零条投影为 MCP 工具**，却占着服务进程注册表
近一半条目，并参与每次 schema 导出与目录快照。

把它们迁到本模块后，宿主可以只保留指令总线与 MCP，而 MCP 工具面一个不少。

## 迁移策略

**不再按命令分组零敲碎打**，改为整体切出——`HistoryVulcan.Shell` 12,712 行连同 `App` 的
前端半边一次迁入，产出 `HistoryAurora.exe`。详见
[前端切出迁移方案.md](前端切出迁移方案.md)（REQ-A1..A4 / B1..B2 / C 阶段）。

按命令分组迁移的方案（曾计划 `log.*` 先行）已被实测否决：前端命令依赖 `ShellWindow`、
`ConsoleView`（21 处引用）、UI 线程，而模块命令只落服务进程，路径根本不通。
且 `log.*` 并非"耦合最浅"——它是全组里最深的。
