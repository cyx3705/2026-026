# 前端切出迁移方案

本文是 HistoryVulcan 前端整体切出为 HistoryAurora 应用的施工方案。四项前置决策已定
（见本仓 DEC-004 与宿主 DEC-049），本文只写怎么做和怎么验收。

## 定下的四件事

| # | 决策 | 影响 |
|---|---|---|
| 1 | Aurora 是**独立应用**（`HistoryAurora.exe`），不是被服务装载的模块 | 它拥有 WPF 生命周期、主窗口与停靠布局 |
| 2 | 宿主**彻底无 WPF** | 危险命令确认必须中继到 Aurora，宿主不再弹框 |
| 3 | Aurora **注册进自己的注册表再上报** | 沿用今日前端机制，不存在模块域名错位问题 |
| 4 | **开掉 Core 冻结**，宿主走 **V4.0** | 模块契约可以收口，`IUiModule` 等可删 |

决策 3 的依据是一次实测教训：模块注册的命令会被强制改域并落到服务进程
（`vulcan.command.run` 变成域 `aurora`、`DataDirectory` 指向服务根）。Aurora 作为应用
自持注册表就没有这个问题——今天那 39 条前端命令正是这样上报的。

## 现状测量（施工前基线）

| 程序集 | 代码量 | 去向 |
|---|---|---|
| `HistoryVulcan.Shell` | 10,245 cs + 2,467 xaml = **12,712** | → Aurora |
| `App` | 1,114 | 拆开，前端半边 → Aurora |
| `HistoryVulcan.Services` | 6,269 | 留宿主 |
| `HistoryVulcan.Core` | 2,462 | 留宿主（本次解冻）|
| `HistoryVulcan.Extensibility` | 703 | 留宿主 |
| `HistoryVulcan.ServiceHost` | 597 | 留宿主 |

`Shell` 内部分布：Docking 2,142 / Themes 2,059 / Console 1,479 / Mcp 1,274 /
Panels 500 / Views 405 / Modules 266 / CommandSurface 196 / 根目录 4,273。

**关键事实：`Services` 与 `ServiceHost` 都不引用 `Shell`。** 整个服务进程只在
`App.xaml.cs:301` 一处调用 `HistoryVulcan.Shell.Mcp.McpCommands.RegisterAll`。
而 `Shell/Mcp/` 的 1,274 行里只有 `RemoteConfirmDialog.cs`（86 行）碰 WPF，
其余 1,188 行是纯逻辑。**解开这一个结，Shell 就能整体搬走。**

## A 阶段：进程切分（行为一比一不变）

目标：宿主无头、Aurora 成为前端 exe。**不改任何命令名、不改交互、模块一行不动。**

### REQ-A1 Mcp 纯逻辑归位

- 动作：`Shell/Mcp/{McpCommands,CommandCatalogCommands,PromptGovernanceCommands}.cs`
  （1,188 行）迁入 `HistoryVulcan.Services`；`RemoteConfirmDialog.cs` 留给前端。
- 验收：`Services` 与 `ServiceHost` 编译期不再出现 `HistoryVulcan.Shell` 引用；
  宿主全套测试通过；`vulcan.mcp.*` / `vulcan.prompt.*` 行为不变。

### REQ-A2 确认通道改为中继

- 动作：服务进程删除 `MessageBoxConfirmation` 与 `RemoteConfirmDialog` 的使用，
  危险命令确认改走 `WebGateway.RequestWebConfirmation` 中继到 Aurora。
- 依据：该通道今天已存在但**不可达**——`ServiceHost` 侧唯一触发条件是源以 `Web:` 开头，
  而删除局域网面后不再有此类会话（宿主 DEC-045 未尽项）。本步正好把它接上。
- 验收：`mcp.confirm=host` 时危险命令弹在 Aurora 而非服务进程；Aurora 未连接时确认**拒绝**
  而不是静默放行；宿主工程移除 `UseWPF`。

### REQ-A3 前端迁入 Aurora

- 动作：`HistoryVulcan.Shell` 整体迁入本仓，与 `App` 的前端半边合成 `HistoryAurora.exe`。
  Aurora 自持 `CommandRegistry`，经既有 IPC 上报能力目录。
- 验收：Aurora 启动后 `/api/health` 显示 `shells=1`；`vulcan.command.list` 全域总数
  **仍为 176**；39 条原前端命令来源变为 `frontend:HistoryAurora`；
  模块 UI（Diana/Janus/Mercury/Minerva）照常显示。

### REQ-A4 宿主收尾

- 动作：宿主删除前端残留与 `--service` 双角色分支，`HistoryVulcan.exe` 只做服务。
- 验收：宿主解决方案内无 `UseWPF` 工程；`vulcan` 域只剩 42 条 `framework:service`；
  宿主代码量降到约 **10k 行**。

A 阶段结束：宿主 ~10k，Aurora ~13k，**模块零改动**。

## B 阶段：页面组件契约

Aurora 定义组件库与页面描述契约，**与现有 `IUiModule` 路径并存**，模块可自行选择时机迁移。

### REQ-B1 页面描述模型

- 页面 = 若干区域；区域内放 Aurora 预设组件（表格 / 表单 / 树 / 日志视图 / 属性面板 / 工具条）。
- 组件的数据来源与动作**一律绑定命令名**，不传递委托或对象引用——描述必须可序列化，
  因为它要跨进程传输。
- 模块发送页面描述，Aurora 渲染；用户交互回落为命令调用。

### REQ-B2 等价性验证

- 验收：拿 Janus 的项目树页做样板，在**不改 Janus 任何 XAML** 的前提下用新契约重画一遍，
  两条路径产出功能等价的界面。这条通过之前不得要求任何模块迁移。

## C 阶段：模块收口

模块按自身节奏从 XAML 改为页面描述。全部迁完后删除 `IUiModule`、`IShellUiAware`
与 Aurora 内的模块程序集装载（含 per-module ALC）。此时才真正拿到"模块不带界面代码"的收益。

- 验收：Aurora 不再反射装载任何模块程序集；Core 中 UI 相关契约清空。

## 风险与已知坑

| 风险 | 应对 |
|---|---|
| Core 解冻后消费方大面积编译失败 | 走 V4.0 主版本号，消费变更摘要逐条列出删除的签名 |
| A3 一次搬 12.7k 行，中途不可用 | A1/A2 先独立落地并各自通过全套门禁，A3 才动 Shell |
| 宿主快照路径已漂移（`z-Publish/host` 不存在） | **A 阶段开工前必须先修**，否则模块仓与 Aurora 都无法从干净状态构建 |
| 模块 UI 在 Aurora 中的装载路径与今日不同 | A3 验收明确要求四个模块的 UI 照常显示 |
| PS 5.1 编码坑（BOM）已踩三次 | 脚本一律带 BOM；`SHA256SUMS` 一律无 BOM（见本仓打包脚本注释）|

## 施工顺序

```
先修宿主快照路径 → REQ-A1 → REQ-A2 → REQ-A3 → REQ-A4 →（宿主发 4.0.0）
                                                    → REQ-B1 → REQ-B2 → C 阶段
```

每步单独过：`build` / `test` / `verify` / `publicApiGate` / `qualityGate` / `format`，
且 A2、A3 各需一次真机启动冒烟。
