# HistoryAurora 文档中心

## 目录规范

根目录只允许三类可见文件夹：

| 前缀 | 含义 | 本仓实例 |
|---|---|---|
| `a-` | 子项目 | 暂无 |
| `b-` | 项目组件 | `b-Code-Studio`、`b-Code-Verify`、`b-Office` |
| `z-` | 跨项目复用元目录 / 发布真值 | `z-Publish` |

`b-Code-Studio/Shell/` 下只允许五个**层目录**，根部不放散文件：

| 目录 | 命名空间 | 层 |
|---|---|---|
| `0-Neutral/` | `HistoryAurora.Shell.Neutral` | 中立 |
| `1-Base/` | `.Base` | 基础层（页面外壳） |
| `2-Components/` | `.Components` | 组件层（别的页面消费的那一层） |
| `3-HostedPages/` | `.HostedPages` | 页面层（Aurora 自持的那几页） |
| `4-Composition/` | `.Composition` | 装配根 |

序号即层号，**依赖只能向下**；命名空间必须跟目录一致。加层要同时改
`HistoryAurora.Module.csproj` 的 `Include` 组与 `LayerContractTests` 的层名表。
详见 `current/技术合同.md` 的 REQ-UI-074 与 `current/有效决策.md` 的 DEC-029。

`z-Publish/` 根部是当前候选，`z-Publish/history/` 是不可变发布归档。**两者都纳入 git；
任何忽略或排除规则不得触碰 `z-*`。**

## 文档分区

| 分区 | 用途 | 读取时机 |
|---|---|---|
| `b-Office/current/` | 现行合同，唯一权威 | 每次进入项目按任务读取 |
| `b-Office/package/` | 对外消费合同的编辑源 | 涉及跨项目复用时 |
| `b-Office/history/` | 版本归档 | 仅在明确要求追溯时，且不得覆盖 current |

`current/` 文件分工：

- `项目概览.md`——定位与进度。只描述状态，不承担合同效力。
- `技术合同.md`——现行要求。每条有编号、目的、要求、验收方式。
- `有效决策.md`——已接受的决策及其原因与替代条件。
- `验证合同.md`——各版本的发布检查项。
- `HistoryAurora_UI风格与嵌入页面规范.md`——颜色令牌、嵌入页结构和顶栏归属（2026-08-22 从 HistoryVulcan package 迁入）。

## 跨项目

本仓是 HistoryVulcan 的界面模块。宿主指令与公开 API 以
`../2026-023-HistoryVulcan/b-Office/package/` 为准，本仓不复述。界面视觉与嵌入页结构以
本仓 `current/HistoryAurora_UI风格与嵌入页面规范.md` 为准。需要邻接项目说明书时先执行
`diana.docs.catalog`，再调用对应通道，不要直接打开别的仓库的 `package`。
