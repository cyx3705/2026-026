# 前端组件缺失需求书（HistoryMercury → HistoryAurora）

- 提出方：HistoryMercury 5.0.0
- 对端：HistoryAurora（页面注册协议 V1，组件集 `stack / text / button / table / input / select / panel / swimlane`）
- 日期：2026-08-25
- 来源：Mercury 从 4.8.1 的三个 XAML 页改为描述化时，逐项对照旧页面得到的差额。
  每一条都**已经有绕法**，写在「当前绕法」列——所以这是排期输入，不是阻塞项。

## 一、缺组件

| # | 组件 | 用在哪 | 当前绕法 | 绕法的代价 |
|---|---|---|---|---|
| C1 | 表格行内控件（单元格模板） | 条目表每行一个「固定 / 移除」按钮 | 行动作改成表格下面一排按钮，逐个 `enabledWhen` | 从「看着哪行点哪行」变成「先选行再下去点」，行数多时来回移动 |
| C2 | 右键菜单（`menu`） | 条目表右键：主操作 / 排除 / 刷新 | 并入同一排按钮 | 与 C1 是同一处损失，叠加 |
| C3 | 弹出层（popup / flyout） | 「策略」按钮弹出的收录策略编辑 | 改成常驻的 `panel` | 三个输入框长期占着页面纵向空间，而它一周也用不到一次 |
| C4 | 带补全的输入框 | 加入框输入指令时的分段补全（域→类→方法→参数） | 纯 `textbox` | 加常驻指令要手打全名，打错只有执行时才知道 |
| C5 | `grid`（多列 / 响应式列宽） | 旧页面窄于 720px 时收起权重/点击/最近打开三列 | 只有 `stack`，列宽固定 | 窄窗口下横向溢出 |

C1 与 C2 可以合成一件事：**表格需要一个「行操作」的表达**，无论它长成行内按钮还是右键菜单。
如果只做一条，做这条。

> 另注：协议草案 §2.1 点名的 `toggleGroup`（`Aurora.Segment.Toggle`）Mercury 用不到，不在本书内。

## 二、缺协议表达（不是组件，V1 加组件解决不了）

| # | 表达 | 后果 |
|---|---|---|
| P1 | **联动取数**：A 组件的选中行驱动 B 处重新取数 | `指令详情` 页在 V1 里根本写不出来，5.0.0 没有恢复它。这是本轮唯一**丢掉、没有绕法**的页面 |
| P2 | **结果回填控件**：把一条指令的返回值写进某个输入框 | 旧页「浏览 → 填回输入框 → 加入」三步只能收成一条 `mercury.shortcut.pick`。每多一个「先选后填」的交互，模块就要多造一条这样的合并指令，而它们只在界面里有意义 |
| P3 | **局部刷新**：只重取某张表的数据 | 只能整页重拉（`aurora.ui.invalidate owner=`），一次状态变化重建整页 |

P1 与 P2 建议放进协议 V2 一起考虑：两者都是「组件之间传值」，P3 则是取数的生命周期，可以单独做。

## 二之二、实测到的一处缺陷（2026-08-25 部署时）

| # | 现象 | 判断 |
|---|---|---|
| D1 | `aurora.ui.invalidate owner=HistoryMercury` 之后，Aurora 去调 `HistoryMercury.ui.describe`，报未知指令并「跳过 HistoryMercury，建了 0 页」 | `ModulePageLoader.ReloadOwnerAsync` 把参数当 **owner** 用来 `Drop`，又当 **domain** 用来拼 `<x>.ui.describe`。两者按设计就不相等（域去掉 `History` 前缀，见宿主手册 §3.3.1 破坏性变更二），因此**任何模块的这条上行通知都拉不到描述** |

传 `owner=mercury` 也修不好：那样 describe 拉得到，但 `Drop("mercury")` 在 `_owners`（存的是
`HistoryMercury`）里找不到，旧页不撤，随后同 id 重注册会失败。修法在 Aurora 侧——
按 `ModuleCommandProbe.ExpectedOwner` 的反函数把 owner 归一成域再拼命令名，
或者干脆让这条命令收 domain 并同步改掉参数名与示例。

Mercury 继续按该命令自己的示例（`owner=HistoryMercury`）发送，不做迁就性猜测。
全量拉取那条路（`aurora.ui.reloadpages` / 冷启动）走 `DescribableOwnersAsync` 探测注册表，
拿到的是域，因此**不受本缺陷影响**——2026-08-25 部署后实测该路径依次调到了
`mercury.ui.actions`、`mercury.ui.describe` 与 `mercury.ui.data view=commands` 并全部成功；
建页条数记在前端控制台，宿主日志里看不到，需在界面上确认。

## 三、Mercury 侧的现状

已按上述绕法交付，不等这些组件：

- `dock.manager`：加入面板（一个输入框 + 四个按钮）+ 策略面板 + 条目表 + 表下一排行动作按钮
- `mercury.commands`：命令目录表，数据取自 `vulcan.command.list`
- 描述里没有引用任何未支持组件，因此 `aurora.ui.missing` 对 HistoryMercury 应为空——
  **这几条缺件不会自动进 Aurora 的台账**（台账只记「用出来的」），需要显式登记：

```powershell
aurora.ui.request component=table.rowactions reason="条目表需要行操作（行内按钮或右键菜单）"
aurora.ui.request component=popup reason="低频编辑器不应常驻占版面"
aurora.ui.request component=input.suggest reason="加入框需要指令分段补全"
aurora.ui.request component=grid reason="窄窗口下需要响应式列"
```

P1 / P2 / P3 是协议问题，不走组件申请通道。

关联：[有效决策](有效决策.md) DEC-018、[技术合同](技术合同.md) REQ-MERC-500。

## 四、Aurora 侧答复（1.7.0，2026-08-25）

**一、缺组件五条全部交付**，绕法可以撤了：

| # | 组件 | 交付形态 | 用法 |
|---|---|---|---|
| C1+C2 | 行操作 | 表格的 `rowActions`：一份声明同时出行内按钮与右键菜单 | 组件清单「行操作」一节 |
| C3 | 弹出层 | `"type": "popup"`，内容仍是面板那三种小组件 | 同上「弹出层」 |
| C4 | 带补全的输入框 | `"type": "input", "suggest": "commands"`，分段补全 | 同上「带候选的输入框」 |
| C5 | 响应式栅格 | `"type": "grid"`，只声明 `min`（一列至少多宽），列数自算 | 同上「响应式栅格」 |

C1 与 C2 按你们的判断合成了一件事。**它们不是两个组件，是同一份声明的两个出口**——
`inline: false` 的动作只进右键菜单，其余两处都有。占位符 `{列名}` 默认取
**被点那一行**的同名列，因此行动作不必再绕 `commands.selected.name` 那种跨节点路径。

四条 `aurora.ui.request` 会在下次 `aurora.ui.requests` 时自动出账
（`table.rowactions` / `menu` / `input.suggest` 进了新的「已交付能力」清单，
`grid` 进了组件清单）。**不必再手工登记，也不必撤销。**

**二、D1 已修**（`aurora.ui.invalidate`）。

你们的判断完全正确，连修法都点到了：owner 与域按设计不相等，1.6.0 在同一个字符串上
用了两个身份。现在在拉取器里各归一一次——**`owner=HistoryMercury` 与 `owner=mercury`
两种都收**，Mercury 继续按命令自己的示例发送即可，不必做迁就性猜测。
回归门禁是 `PageInvalidateContractTests`（此前本仓没有一条用例走这条路径，
所以这个缺陷只能在真机上现形，你们那次部署是它第一次被看见）。

**三、协议表达 P1 / P2 / P3 暂未做**，理由与现状：

- **P1 联动取数**：本轮用另一条路把它绕开了——`指令详情`页由 Aurora **自建**
  （命令集也是，它整页消失过一轮，见 DEC-015），不走描述协议，因此不需要 P1。
  这不等于 P1 不成立：模块自己的页面要做"选中驱动取数"仍然写不出来。
  它与 P2 一起留给协议 V2。
- **P2 结果回填控件**：同上。当前每多一个"先选后填"就要多一条合并指令的代价仍在。
- **P3 局部刷新**：单独成立，未做。目前仍是整页重拉。

P1/P2/P3 三条会作为协议 V2 的输入。本轮没做，也没有把它们记成已做。

**四、本轮的验证边界（请注意）**：以上组件**全部只有自动化覆盖，尚未在真机上渲染过一次**。
1.7.0 还没有发布也没有部署，真机宿主上跑的仍是 1.6.0。
等发布部署后，Mercury 那两个页面会是这批组件的第一个真实使用者。

**五、组件区现在是公共区**（DEC-016）。
下次再缺什么，可以直接来 `b-Code-Studio/Shell/Widgets/` 提交，不必先写需求书等排期；
五条门槛写在组件清单「公共组件区」一节。
需求书这种形式仍然有用——尤其是"当前绕法 / 绕法的代价"这两列，
它让排期能按代价而不是按嗓门来排。这次就是照着这两列的顺序做的。
