# 前端命令归属判定表 V1.0

> 2026-08-19 依 HistoryVulcan DEC-050 与 Aurora DEC-006 逐条判定。
> DEC-006 明确要求「39 条前端命令逐条判定，不一刀切」，本表是那次判定的结果与依据。
> 现行约束见 [`../current/技术合同.md`](../current/技术合同.md) REQ-UI-001。

## 判定标准

来自 DEC-050：**指令域由谁实现决定，不由历史归属决定。**

| 判定 | 标准 | 结果 |
|---|---|---|
| 归 Aurora | 需要 UI 线程、剪贴板、窗口、对话框，或其数据由界面组件持有 | 改域 `aurora.*` |
| 归服务侧 | 只依赖命令总线、注册表、设置、数据根 | 保留 `vulcan.*` |

判定依据取自源码实测，不靠命令名猜测——`vulcan.command.run` 就是一条名字在
`vulcan.command.*` 下、实际却毫无 UI 依赖的反例（已于 REQ-A6 搬回服务侧）。

## 一、总量核对

宿主 3.13.0 运行时 `vulcan` 域 81 条中，来源 `frontend:HistoryVulcan.Frontend` 的有 **39 条**：

| 类 | 条数 | 备注 |
|---|---|---|
| `ui` | 21 | 其中 4 条经 `RegisterWindowVerb` 辅助注册，不是描述符字面量 |
| `log` | 10 | 全部集中在 `BuiltinCommands.Log.cs` |
| `app` | 4 | about / opendata / theme / window |
| `command` | 4 | copyexample / help / history / run |

`HistoryVulcan.Shell` 工程里能搜到 48 个 `vulcan.*` 注册点，比 39 多出 9 条
（`app.close/focusconsole/get/hide/set/quit/show` 与 `module.*`）——那些是**嵌入模式**的
重复注册，独立宿主下由服务侧注册胜出，不在本次迁移范围内。清点时不要按 48 算。

## 二、判定结果

### 归服务侧，保留 `vulcan.*`（2 条）

| 命令 | 判定依据 | 状态 |
|---|---|---|
| `vulcan.command.run` | 只用 `Bus` + 数据根，原实现连 `RequiresUiThread` 都没标 | **已搬回**（REQ-A6，单侧） |
| `vulcan.command.help` | `HelpList(s.Bus.Registry)` / `HelpDetail(...)`，纯注册表查询与文本拼装 | **已加服务侧**（双侧注册） |

`command.help` 与服务侧已有的 `command.list` / `command.show` / `command.domains` 属同一族
（都是注册表查询）。搬迁时应一并评估是否与 `command.show` 合并——两者都做「按名查单条命令
详情」，重复度高。

### 施工中发现：`help` 必须双侧注册，不能单侧搬走

初次施工按 `command.run` 的做法单向搬迁（删前端、加服务侧），结果 **35 个测试转红**：
`ShellWindow.ChromeMenus` 在构建期用 `_bus.Validate` 逐条校验菜单指令，而测试跑的是
**嵌入模式**（无远端），前端注册表里没有 `help` 就直接抛
`菜单引用了无效指令 [vulcan.command.help]`。

查证后发现仓里早有先例：`app.get` / `app.set` / `module.*` 本来就是**两侧都注册**——
嵌入模式用前端那份，独立模式服务侧胜出（实测运行时 `vulcan.app.get` 的 `Source` 是
`framework:service`）。`help` 属于同一类，前端那份不能删。

`run` 与 `help` 的区别在于：`run` 在嵌入模式下也没有菜单入口引用它，删掉不影响任何界面；
`help` 有。**判定「归服务侧」不等于「从前端删除」**——还要看嵌入模式是否有界面引用它。
本表第二节的「归服务侧」一栏据此细分为「单侧」与「双侧」。

### 连带修复：`Validate` 与 `ExecuteAsync` 的口径不一致

同一次施工暴露了一个先前潜伏的缺陷：`CommandBus.ExecuteAsync` 配置了 `RemoteExecutor`
时会把本地查不到的指令**中继**出去，而 `CommandBus.Validate` 只查本地注册表并报
「未知指令」。两者对「什么是有效指令」的判断从来不一致。

后果是：任何一条命令从前端搬到服务侧后，引用它的菜单会在**构建期抛异常**，
尽管点下去其实能正常执行。B 阶段要把 37 条命令搬去 Aurora，这个缺陷会成片触发。

已修：配置了 `RemoteExecutor` 时，本地查不到判为「无法在本进程判定」而非无效；
无远端的嵌入模式仍硬报错（那时本地注册表就是权威，笔误必须当场暴露）。

### 归 Aurora，改域 `aurora.*`（37 条）

**`ui` 类 21 条** —— 全部操作停靠布局与窗口，`RequiresUiThread = true`：

`show` `hide` `float` `reset` `windows` `autohide` `max` `floatstate` `restore` `dock` `ratio`
`layoutsave` `layoutload` `layouts` `layoutreset`
`panels` `panelshow` `panelset` `panelreload` `selectfile` `selectdirectory`

其中 `selectfile` / `selectdirectory` 弹系统对话框，是 REQ-CMD-012 标注的**交互式指令**，
只在有 UI 的宿主注册——它们随 Aurora 走后，宿主侧不应再有任何形式的替身。

**`log` 类 10 条** —— 全部操作控制台视图状态：

`level` `source` `class` `keyword` `mute` `autoscroll` `clear` `export` `copy` `focus`

`log.export` 需注意：REQ-CMD-012 要求它省略 `path` 时不得弹 `SaveFileDialog`，
必须写入默认路径并回传绝对路径。迁移不得破坏这条。

**`app` 类 4 条**：

| 命令 | 依据 |
|---|---|
| `about` | 弹 `MessageBox` |
| `theme` | 切换主题资源字典，`RequiresUiThread = true` |
| `window` | 设置主窗口状态 |
| `opendata` | `Process.Start("explorer.exe", …)`。虽不占 UI 线程，但让无头服务去拉起资源管理器正是要避免的形态 |

**`command` 类 2 条**：

| 命令 | 依据 |
|---|---|
| `copyexample` | `Clipboard.SetText`，`RequiresUiThread = true` |
| `history` | 读 `s.History`，而写入方是 `ConsoleView.xaml.cs:99` 的 `_history.Add(e.Message)`——**控制台输入史，数据由界面组件持有** |

`command.history` 曾是本次判定里唯一「既不占 UI 线程、也无 UI 迹象」的条目，
若只按静态标记判会误判为服务侧。追到写入方才能确定它记录的是**你在控制台里敲过什么**，
不是总线执行史——归 Aurora。

## 三、施工次序

1. ~~`command.help` 搬回服务侧~~ **已完成**（双侧注册，见上）；
2. 其余 37 条随前端整体切出，一次性改域为 `aurora.*`；
3. 与组件键名改名（DEC-005）**同批发布**——两次破坏性变更分批放出等于让模块适配两轮。

### 搬迁前必须逐条确认的三件事（第 1 步的教训）

| 检查 | 不查的后果 |
|---|---|
| 嵌入模式是否有菜单/界面引用它 | 构建期抛「菜单引用了无效指令」，成片转红 |
| 搬到服务侧后 MCP 可见性是否变化 | 前端注册的 `PolicyVisible` 恒为 false，搬过去默认可见——`command.run` 就因此一度被暴露给远程（REQ-A6 已按名硬排除） |
| 相对路径 / 数据根语义是否改变 | `DataDirectory` 在两侧不同值，脚本类命令会集体失效 |

## 四、验收

- 迁移后 `vulcan.command.domains` 中 `vulcan` 域减少的条数 = `aurora` 域增加的条数 = 37；
- 宿主侧不再注册这 37 条中的任何一条；
- MCP 可见工具数不变（这 39 条 `PolicyVisible` 本就全为 false）；
- `log.export` 无 `path` 时仍不弹对话框、仍回传绝对路径。
