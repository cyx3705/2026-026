# 前端切出迁移方案

> **已归档（2026-09-22，Aurora 1.26.0）**：本文是历史施工方案，不再是现行合同。仍然有效的结论已提炼进
> [技术合同](../current/技术合同.md)「方案文档提炼的现行要点」一节；与现行合同冲突时以 current 为准。

本文是 HistoryVulcan 前端整体切出为 HistoryAurora 应用的施工方案。四项前置决策已定
（见本仓 DEC-004 与宿主 DEC-049），本文只写怎么做和怎么验收。

## 定下的四件事

| # | 决策 | 影响 |
|---|---|---|
| 1 | Aurora 是**独立应用**（`HistoryAurora.exe`），不是被服务装载的模块 | 它拥有 WPF 生命周期、主窗口与停靠布局 |
| 2 | 宿主**彻底无 WPF** | 危险命令确认必须中继到 Aurora，宿主不再弹框 |
| 3 | Aurora **注册进自己的注册表再上报** | 沿用今日前端机制，不存在模块域名错位问题 |
| 4 | **开掉 Core 冻结**，宿主走 **V4.0** | 模块契约可以收口，`IUiModule` 等可删 |

决策 3 的依据是一次实测教训：模块注册的命令会被强制改域并落到服务进程
（`vulcan.command.run` 变成域 `aurora`、`DataDirectory` 指向服务根）。Aurora 作为应用
自持注册表就没有这个问题——今天那 39 条前端命令正是这样上报的。

##### 四个只在运行期暴露的坑

这四个全部编译通过、全部在启动时才炸，其中三个的失败方式是**静默的**：

1. **相对命名空间解析断裂**。原代码在 `HistoryVulcan.Shell` 下，`Core.X` 顺层解析到
   `HistoryVulcan.Core.X`；改成 `HistoryAurora.Shell` 后不再成立。30 处需显式限定。
   这条是编译期报错，最容易发现。
2. **pack URI 用的是程序集名，不是命名空间**。命名空间改名把
   `/HistoryVulcan.Shell;component/` 带成了 `/HistoryAurora.Shell;component/`，
   而程序集名是 `HistoryAurora`。运行期 `FileNotFoundException`。
3. **`Link` 路径决定资源名**。`Link="Shell\%(RecursiveDir)…"` 把资源打到
   `shell/themes/…`，而 URI 找 `themes/…`，运行期 `IOException 找不到资源`。
   去掉 `Shell\` 前缀即与迁出前结构一致，URI 一行不用改。
4. **端点文件属于宿主的数据根，不是自己的**。迁出前两者共用 `HistoryVulcan` 身份，
   `Path.Combine(paths.Root, "service", "endpoint.json")` 恰好是对的；切分后 Aurora 的
   身份变成 `HistoryAurora`，同样的写法会去找一个永不存在的文件，**且失败方式是静默降级**
   ——连不上就转本地模式，用户只看到"某些命令不见了"。现按宿主身份显式解析。

##### 三项行为变更

- **不再派生后台**。迁出前前端连不上就用 `--service` 把自己再拉起来一份；现在宿主是
  另一个产品，Aurora 既不知道它装在哪，也不该替它决定何时启动。宿主由
  `vulcan.svc.autostart` 注册登录启动。未就绪时如实报告，不猜路径。
- **入口点不带 `--service` / `--export-command-manual` / `--repair-autostart`**。
  后两者是宿主职责——前端没有权威注册表，导出的手册会是残缺的。
- **单实例互斥锁改名**。与宿主前端同名会让两者互相判定对方已在运行而拒绝启动，
  症状是"点了图标没反应"。

##### 改域（DEC-006）已完成：36 条 `vulcan.*` → `aurora.*`

实测结果：`aurora` 域 1 → **37** 条，`vulcan` 域 66 → **30** 条，全域总数不变。

**保留 `vulcan.*` 的例外（协议名，不是实现名）**：宿主按字面量中继
`vulcan.app.close` 等生命周期命令，`vulcan.module.*` 亦由宿主在安装/移除时中继到前端
卸载同名 UI 快照（DEC-043）。这些名字是**宿主↔前端的协议**，改了中继就断。
DEC-050「域跟随实现方」对它们不适用——它们的实现确实在 Aurora，但名字的所有者是协议。
其余命令走 `Bus.FrontendExecutor` 泛化中继，不依赖具体名字，可以自由改域。

###### 改域时踩到的两个坑

**一、`Name` 是变量的注册器会被批量同步漏掉。** `RegisterWindowVerb` 用
`Name = name` 构造描述符，按 `Name = "aurora.*"` 做的 `Domain` 批量同步匹配不到，
于是 4 条命令处于「名是 `aurora.ui.show`、域是 `vulcan`」的状态——
在 `command.list domain=vulcan` 里能查到一条名叫 `aurora.*` 的命令，肉眼很难注意到。
批量改名后必须按**运行时**的域计数核对，不能只看源码替换数。

**二、`web.frontendcatalog` 是持久化设置，且按客户端名做键，没有回收机制。**
客户端名从 `HistoryVulcan.Frontend` 改成 `HistoryAurora` 后，旧目录成了永远不会被清理的
孤儿：36 条幽灵命令跨重启存活，与新注册的 37 条并存，域计数一度显示 `vulcan` 70 +
`aurora` 33（凭空多出 36）。重启宿主**无效**，因为它存在 settings.json 里。

> **待办（宿主侧）**：目录缓存应在客户端改名或长期不再出现时可回收，
> 否则任何一次前端更名都会留下一份永久幽灵目录。当前只能手工删除该设置键。

###### 搬迁测试时踩到的坑：改名脚本会误伤断言

批量把 `vulcan.*` 改成 `aurora.*` 时，测试里有三类字符串**不该改**，而正则区分不了：

| 类别 | 例子 | 为什么不能改 |
|---|---|---|
| 中继协议名 | `vulcan.app.close`、`vulcan.module.*` | 宿主按字面量发过来，改了中继就断 |
| Services 所有的命令 | `vulcan.command.list` | 由宿主实现，Aurora 只是引用 |
| 主题文件名断言 | `ShellTokens.Dark.xaml` | 是文件名不是命令名，随主题文件改名而变 |

前两类各造成一批用例失败，第三类造成深色主题用例失败。

> **教训**：批量改名后不能只看编译通过，必须跑测试；失败要逐条判性质，
> 不要统一当成「适配问题」一改了之——其中两类恰恰说明源码是对的、测试改错了。

## B 阶段：页面组件契约

Aurora 定义组件库与页面描述契约，**与现有 `IUiModule` 路径并存**，模块可自行选择时机迁移。

### REQ-B1 页面描述模型

- 页面 = 若干区域；区域内放 Aurora 预设组件（表格 / 表单 / 树 / 日志视图 / 属性面板 / 工具条）。
- 组件的数据来源与动作**一律绑定命令名**，不传递委托或对象引用——描述必须可序列化，
  因为它要跨进程传输。
- 模块发送页面描述，Aurora 渲染；用户交互回落为命令调用。

### REQ-B2 等价性验证

- 验收：拿 Janus 的项目树页做样板，在**不改 Janus 任何 XAML** 的前提下用新契约重画一遍，
  两条路径产出功能等价的界面。这条通过之前不得要求任何模块迁移。

## C 阶段：模块收口

模块按自身节奏从 XAML 改为页面描述。全部迁完后删除 `IUiModule`、`IShellUiAware`
与 Aurora 内的模块程序集装载（含 per-module ALC）。此时才真正拿到"模块不带界面代码"的收益。

- 验收：Aurora 不再反射装载任何模块程序集；Core 中 UI 相关契约清空。
